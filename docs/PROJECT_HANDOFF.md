## 現在の状態

- React + Vite + TypeScript + Dexie。外部のアプリ用サーバーやAPIキーは不要。
- Phase 1：単語の登録・編集・削除、性・活用・例文・教材タグ、CSV／タブ区切り取り込み、SRS、4出題形式、既知マーク。
- Phase 2：朝晩の5分クイズ、通知・新規単語数・テスト範囲設定、統計・カレンダー・連続記録、音声プレイヤー、JSONバックアップ追加復元。
- スマホ優先の4タブ：今日／単語帳／記録／その他。ホームの主操作は通常復習。設定・任意項目・デモ説明は必要な時だけ開く。
- 声に出して答えた自己チェックで文字入力を省略可能。任意のブラウザ音声入力も利用可能。
- 24時間以上あいた通常復習の自己採点を自動集計し、定着の参考値を表示。
- 通常とデモはIndexedDB・localStorageを分離。デモ初期化で通常データを消さない。
- 直近の検証：本番ビルド成功、単体15件・ブラウザ11件合格。390px／320pxのスマホ幅、主要操作の画面内表示、44pxの操作領域を確認。

## 決めたこと

1. 学習成果と入力負担を優先する。機能を増やすこと自体を目的にしない。
2. Appleの設計原則を参考に、明快な階層・余白・統一した操作・段階的な開示を使う。スマホで使いやすくする。
3. 日記、使った文型のチェック、学習時間の手入力は必須にしない。これらの新テーブル追加案は現時点で採用しない。
4. 「試験7日前から全カードを毎日」という固定ルールは直接の根拠を示せないため採用しない。SRSはEF 2.5、1→3→7日を含む既存の変種を維持。これ自体の最適性も保証しない。
5. 研究が支持する一般的な想起・分散練習と、アプリ固有の未検証の仮説を区別する。文献のネットワーク再確認に制約があったことも記録する。
6. 無関係な全文読み直し・同じ検証の反復・同じ許可確認を避ける。必要な差分だけ実装して、報告も短くする。
7. SRSやDexie構造を変える場合は、具体的な変更案を説明して事前承認を得る。

## 制約・注意

- 学習データは端末・ブラウザ・オリジンごとの保存。同じGitHub／CodexアカウントでもPCとスマホに自動同期しない。移行はJSONバックアップを使う。
- JSON復元は追加方式。同じファイルを繰り返し復元すると重複する。設定の置き換えは明示チェック時のみ。
- 通知はアプリを開いている間。ブラウザを閉じた状態やスリープ中の定時通知は保証しない。
- 音声再生は端末の音声に依存。音声入力はブラウザ提供元に音声を送信し、通信を要する場合がある。未対応・拒否時も学習は継続できる。
- 自動テストの音声API確認と、実端末での録音・発音・可聴性の検証を混同しない。
- 詳細統計は自己採点の参考値で、標準化テストやCEFRの代替ではない。

## 開発・公開

既存チェックアウト `/workspace/word-repetition-app` を使用。開発手順はAGENTS.mdとREADME.mdを優先。通常の画面変更では既存部品を再利用する。

```sh
npm ci
npm run dev -- --port 5173 --strictPort
npm run build
npm test
npm run test:e2e
```

E2Eは4173を空けて実行。`/usr/bin/chromium` または `CHROMIUM_PATH` を使用する。

公開時は `npm run build:pages` を使用し、`/word-repetition-app/` のパスで確認する。ソースは `mon-francais-web`、生成物は `gh-pages`。`.github/workflows/publish-pages.yml` も参照する。標準ビルドのdistをそのまま公開しない。Git pushと公開サイトの実表示確認は区別する。
